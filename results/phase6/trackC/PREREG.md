# Phase 6, Track C (eye-tracking validity): pre-registration

Written 2026-11-02 before any sample-based feature, noise-decomposition or event-detection result was computed on real labels. Later changes are logged in `DEVIATIONS.md`. Plan: `docs/phase6_plan.md`; source: `docs/review_5c_eyetracking.md` M1, M3, M6. Code: `scripts/phase6_trackC_*.py`. Scratch caches are kept outside `results/`.

## C1. Sample-based dwell features without event detection (webcam noise)

**Data and noise.** The decimated 30 Hz gaze cache of the webcam study (`results/phase3/webcam_noise/cache_30hz/`, 75 participants) and the same pre-registered noise: `np.random.default_rng([20261102, draw, participant])`, standard-normal offset (2), jitter (2 x trials x samples) and uniform loss draw, in that order, rescaled by level. Levels L = 0, 1, 1.5, 2, 3, 4 deg; draws 1, 2, 3 for L > 0 (level 0 is noise-free, one run). Full noise = offset (Rayleigh mean L) + white jitter SD 0.5 + 0.25 L per axis + 10% i.i.d. sample loss. The full-noise I-VT runs are NOT recomputed: the stored out-of-fold (OOF) scores of the webcam study are reused (`ALLz_fixed_lr_30_L*_d*_oof.csv.gz`); one of them (L = 1, draw 1) is recomputed as a check of the new code path (scores must match to 1e-9).

**Decomposition.** At every level and draw the three components are applied alone, using the same random numbers: offset only, jitter only, sample loss only; plus all three together. Each is run with (a) fixed I-VT (the clean pipeline, 30 deg/s) and (b) sample-based features. Offset-only at level L uses offset L and no jitter or loss; jitter-only uses SD 0.5 + 0.25 L; loss-only uses 10% loss.

**Anchored condition (exploratory).** The project notes (webcam PREREG, section 2) hold a measured webcam source: Kaduk et al. 2024, Labvanced 30 Hz, accuracy 1.45 deg, RMS sample-to-sample 1.66 (x) and 1.42 (y) deg, sample loss 1.5 to 3.1%. Anchored noise: offset Rayleigh mean 1.45 deg, white jitter SD per axis = RMS-S2S / sqrt(2) (1.174 deg in x, 1.004 deg in y), loss 3%. Draws 1, 2, 3. Run with I-VT and with sample-based features. Not part of the decision family.

**Sample-based features** (computed on the noisy 30 Hz samples; no velocity threshold, no minimum duration, no fixation mask). A sample is valid when x and y are finite. A face area is the picture rectangle of the clean pipeline (`QUAD_RECTS`, no padding). Time windows are the pipeline's: dwell_1 = [200, 1000) ms, dwell_2 = [1000, 5000) ms, dwell_b1..b5 = [0,500), [500,1000), [1000,2000), [2000,3500), [3500,5000) ms after display onset.
- `dwell_1`, `dwell_2`, `dwell_b1..b5`: share of valid samples in the window that lie inside the face area (NaN when fewer than 20% of the window's samples are valid; the pipeline's median imputer then applies).
- `n_visit`: number of entries into the face area in [0, 5000) ms. An entry is a valid sample inside the area whose previous valid sample (gaps skipped) is not inside it, or that has no previous valid sample in the window.
- `lat_first`: time of the first valid sample inside the area in [0, 5000) ms; 5000 if none.
- `first_fix`: 1 for the face holding the earliest valid in-area sample of the trial, else 0.
- `pupil_trial`, `pupil_face`: as in the pipeline (blink-padded interpolation, baseline [-200, 0) ms), except that `pupil_face` averages over valid samples inside the area in [1000, 5000) ms (the I-VT version averages over fixation samples), with at least 3 such samples.
- `n_fix` is not defined without events and is dropped. Primary sample-based model = the other 12 features of ALL_z (z-scored per participant within set, per-image means over presentations, exactly as `build_table_30`). Secondary model "SB+seg" adds `n_seg` = number of runs of at least 2 consecutive valid in-area samples (at least 66.7 ms of contiguous in-area samples) in [0, 5000) ms, as the closest event-free analogue of `n_fix` (reported separately; it is a mild form of event detection).

**Model and folds.** ALL_z LR via the track's `run_grid` (median imputer, standard scaler, balanced logistic regression, C in {0.01, 0.1, 1, 10}, 4-fold inner participant-grouped CV, AUC scoring), frozen folds `results/phase2/delmas_raw/folds.json`, all six group sets. I-VT features for new decomposition runs come from `edd.delmas_fast.trial_features_batch` (numerically identical to the pipeline to about 1e-13, verified on level 0 and on the L = 1 check).

**Metric and tests.** AUC = image-level, pooled within each of the six sets on repeat-averaged OOF scores, mean over sets (the non-inferiority definition); a level's AUC is the mean over its 3 draws. Reference: P4 SVM at 1000 Hz, `results/phase2/delmas_raw/checkpoints/P4_svm_1000_oof.csv.gz`, AUC 0.7811. Paired participant-cluster bootstrap, 2000 resamples, seed 0, participants resampled within each set, identical resamples for the reference and all candidates (the procedure of `scripts/phase3_webcam_noise.py::stage_stats`). Delta = AUC(candidate) - AUC(reference). One-sided non-inferiority p = (1 + #{Delta <= -0.02}) / 2001; non-inferior when the Holm-adjusted p < 0.05.
- Primary family (Holm over 6 tests): sample-based ALL_z-minus-n_fix, all three noise components, at L = 0, 1, 1.5, 2, 3, 4.
- All other rows (SB+seg, decomposition, anchored, I-VT comparison rows) are exploratory: raw p and a Holm p within the row's own family (one condition across levels) are reported, with no claim of confirmatory status.
- Also reported for each level: Delta of sample-based minus I-VT (same level, paired bootstrap CI, no margin); Delta to the model's own clean result; ΔAUC with 95% percentile CI.
- Checks that must pass: level-0 I-VT AUC reproduces 0.7854 (bit-identical OOF to the stored webcam-study level-0 file); the full-noise I-VT check above; the vectorised sample-based features match an unvectorised reference implementation written in the script on a subset of trials.
- Jitter anchoring: the existing levels are kept for the main grid; the anchored condition is the measured-precision test.

## C2. Event-detection validity per sampling rate

**Data.** EyeLink 1000 Hz EDF files of Delmas et al., 5 s parallel displays (the pipeline's `edd.delmas_raw.read_edf_fast` and its trial cutting), the 1000 Hz signal decimated with `edd.delmas_fast.degrade_batch` to 1000, 500, 250, 120, 60 and 30 Hz, and the fixed I-VT of the paper pipeline (30 deg/s, differentiator half-width h = max(1, round(0.004 fs)) samples, minimum 60 ms, a sample next to a gap is not a fixation sample). All 75 participants, all 64 trials. EyeLink parser events (fixation start, end, mean gaze) come from the same EDF files; onset in [0, 5000) ms after display onset.

**Per rate:** fixations per trial (I-VT events with onset in the display window, anywhere on the screen; and on-face fixations whose centroid is inside a face area); mean and median fixation duration (pooled over fixations, and mean of participant means); share of the window inside fixations; the same numbers for the EyeLink parser at 1000 Hz as the reference.

**Agreement with the parser.** Exact definition (primary): per-face fixation counts per presentation, i.e. the number of events with onset in [0, 5000) ms whose centroid (I-VT) or mean gaze position (parser) is inside the face area, for each of the 4 faces of each trial; Pearson r between the I-VT count at rate r and the parser count over all (participant, trial, face) cells (n = 75 x 64 x 4 = 19,200). Secondary units, all reported: participant x image (mean over presentations, the classifier's unit), image level (mean over participants of the per-image value), within-participant (cell values minus participant means), and Pearson r of dwell. Dwell: I-VT dwell_2 (fixation samples inside the face in [1000, 5000) ms / 4000 ms, and dwell_1 on [200, 1000) ms) against parser dwell (parser fixation time clipped to the window, assigned to the face containing its mean gaze position, / window length), same units as above; also sample-based dwell (share of valid samples) against parser dwell. Also count ratio (mean I-VT count / mean parser count).

**Provenance of 0.77 vs 0.68.** Label-free re-computation of the agreement from the stored tables (`data/derived/delmas_raw_face_trials.csv.gz`, columns `el_nfix` and `n_fix`) under every plausible aggregation: trial x face, participant x image (mean, sum), per set after `build_tables`-style aggregation, image-level, pooled over rates, within-participant, Pearson and Spearman. The definition that returns 0.97 / 0.88 / 0.77 at 120 / 60 / 30 Hz is reported if one exists. The verdict says which definition the paper should state; the primary definition above is fixed in advance, and no definition is chosen for the number it gives.

**Smallest detectable saccade.** Analytical: with differentiator half-width h = max(1, round(0.004 fs)), the velocity span is 2h/fs and the 30 deg/s threshold needs a displacement of at least 30 x 2h/fs deg between the two samples, so no saccade of smaller amplitude can exceed the threshold (noise-free bound; the anti-aliasing filter and noise raise it). Empirical: for consecutive parser fixations in a trial (gap at most 150 ms, both onsets in the display window), amplitude = distance between mean gaze positions; a transition is "resolved" at rate r when the I-VT fixation id at the sample nearest the midpoint of the first parser fixation differs from that at the second, both being fixation samples; "merged" when the ids are equal; "lost" when either midpoint sample is not in a fixation. Resolved share by amplitude bin: <0.5, 0.5-1, 1-2, 2-4, 4-8, >=8 deg.

## C3. Data-quality table per dataset

Datasets: Delmas (EyeLink 1000 Hz), Celniak (Tobii), Chen (EyeLink), Preti, Colasanti, plus Mazza and Liar's Dice only if the loader shows eye-tracking quality data (otherwise omitted). Columns: device, sampling rate (from sample timestamps where samples exist, otherwise from the source), eye(s) recorded, head support, % missing or invalid samples (definition stated per dataset), % trials or participants excluded (definition stated), calibration or validation error where present in the data, class difference in quality (guilty vs innocent, familiar vs control, or group) where there are class labels. "Not available" where a value cannot be obtained from the project data. Quality values are descriptive; the class comparison reports medians per class and the AUC of the quality variable for the class label with a participant bootstrap CI. No quality value is used to select or drop data.
