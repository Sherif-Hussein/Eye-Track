# PREREG: Phase 6 Track B (refit-aware inference): B1 and B2

Written 2026-11-02, before any computation on real labels or permuted labels in this track. Later changes go in `DEVIATIONS.md` only. Code: `scripts/phase6_trackB_*.py` (new files only). Nothing in `src/`, `paper/`, `results/phase2..5` or any frozen file is modified; stored files are only read.

Question (Stats review M1 and M2; Sci Rep and Q1 editors on Celniak): the Phase 4 paired bootstrap conditions on fitted models and on fixed out-of-fold scores. B1 replaces it, for the seven pre-registered primary tests, by a label-permutation test that re-runs the WHOLE nested pipeline (folds rebuilt where the design needs it, C and all other hyperparameters re-tuned) for the honest baseline and for our pipeline. B2 gives the best-of-216-grid null for the Celniak published-protocol reproduction.

## 1. B1: tests, pipelines and statistics

Every pipeline below is the code that produced the stored result; it is imported or re-used unchanged and run with the same settings, only with permuted labels. Python numerics are single-threaded per process (`OMP/OPENBLAS/MKL_NUM_THREADS=1`).

### Permutation scheme (per permutation i of a task)
- Person-labelled tasks (Celniak, Preti, both Mazza tasks): the participant-level labels are permuted between participants (for Mazza the experimental-group label is permuted between participants and the binary label is derived from it, so fold strata keep their meaning). Features are untouched.
- Delmas (image labels, known vs unknown face, within participant): the labels are permuted among each participant's own images, independently in each of the six group-sets; counts per participant are preserved. The same permuted labels go to both arms (arms are matched by participant and image id).
- Chen (trial types familiar / control 1 / control 2, within participant): the trial-type label is permuted among each participant's own trials; the binary label is familiar vs control derived from it; both arms use the same permuted trial types.
- Folds: Delmas and Chen folds do not depend on labels (participant-disjoint, frozen) and are reused. Class-paired folds are REBUILT from the permuted labels: Celniak `order_matched_folds(permuted labels, test order, 2026 + repeat)` (the function of `phase2_celniak_screen.py`; the participants' test order is kept with the participant); Preti `edd.folds.make_repeated_folds(units, permuted labels, 3, 2026)`; Mazza `StratifiedKFold(10, shuffle, 2026 + repeat)` stratified by the permuted group. The same rebuilt folds go to both arms of a task. Identity-run folds equal the frozen folds (checked).
- Preti A and B share each permutation (same permuted labels and folds); the other five tests have their own permutations.
- Seeds: permutation `i` of a task uses `numpy.random.default_rng([20261201, task_id, i])` with task_id: delmas 1, chen 2, celniak 3, preti 4, mazza_g2_vs_g3 5, mazza_guilty_vs_innocent 6. A permutation is a pure function of (task, i), so runs can be resumed and extended.
- Every model fit inside a permutation (inner folds, C or C x gamma grid, thresholds, Chen rate-rule peak) is re-done from scratch on the permuted labels with the seeds of the stored pipeline.

### Statistics
For each task and permutation: S_base, S_ours, delta = S_ours - S_base. Observed values S_base*, S_ours*, delta*. N = number of recorded permutations of the task.
- Single AUC vs chance (one-sided, the direction "detects"): p_single = (1 + #{S_null >= S*}) / (1 + N), separately for baseline and ours. The lower tail p_low = (1 + #{S_null <= S*}) / (1 + N) is also reported (it is the relevant tail for AUCs below 0.5, e.g. Preti A baseline). For Chen the single statistics are person AUC and detection rate.
- Null 95% range of each single S and of delta: the 2.5th and 97.5th percentiles of the null values; also null mean and SD.
- Superiority tests (tests 2-7, as pre-registered in Phase 4: H1 delta > 0): p_delta = (1 + #{delta_null >= delta*}) / (1 + N). For Chen the statistic is detection rate (the pre-registered metric); the person-AUC delta is descriptive.
- Delmas non-inferiority (margin 0.02, H0: delta <= -0.02): the permutation null of delta is centred near 0 and is not a null for H0, so the refit-aware non-inferiority p-value is the null-shift form: p_NI = (1 + #{delta_null >= delta* + 0.02}) / (1 + N). It assumes that the sampling spread of delta under no signal approximates its spread at the true effect (stated limitation). Also reported: the lower bound delta* - 1.645 x SD_null(delta) and the usual permutation p for delta (as in the superiority form, descriptive).
- Holm: the seven refit-aware p-values (p_NI for Delmas, p_delta for tests 2-7) in one family, alpha .05, same family as Phase 4. Reported next to the Phase 4 bootstrap p and Holm p.
- No other test is added. Per-set Delmas AUCs, Chen realised FPR and detection of each arm are stored descriptively.

### N and compute
- Target 1,000 permutations per task, floor 200. Total budget for B1 about 10 hours wall time on 7 worker processes (`multiprocessing`, spawn). N per task is fixed after timing one permutation per task in a scratch folder (outputs discarded) and recorded in Amendment 1 below, before any permutation is recorded in `results/phase6/trackB`.
- Scheduling: jobs are (task, permutation index) and are released in blocks of 25 permutations per task, task by task, so every task reaches the same number of completed blocks before any task goes further. Each finished permutation is appended to `perms/<task>.jsonl` at once; a progress log and a consolidated checkpoint (`results.json`, partial) are written every 25 completed permutations. A restart skips finished (task, i). If the budget is reached, N is the number of complete blocks, never below 200 (if 200 is not reachable the stop is reported as is).
- All recorded permutations are used. None is dropped, replaced or re-drawn after seeing results. A failed permutation (exception) is logged and retried once with the same seed; a second failure is reported.

## 2. B2: Celniak best-of-grid null

- Data, features and model: as the class-paired reproduction in `scripts/audit_followup.py` part A: `data/derived/celniak_slide_features.csv`, `PAPER_FEATURES` (19), pipeline StandardScaler -> `SelectKBest(f_classif, k)` -> `SVC(rbf, C, gamma)` fitted inside each fold; grid k in {3,5,7,10,13,all} x C in {0.001,0.01,0.1,1,10,100} x gamma in {1e-4,1e-3,1e-2,0.1,1,10} = 216 points (full grid); class-paired folds (one guilty plus one innocent participant per test fold, 19 pairs plus one leftover = 20 folds); for each grid point slide scores are averaged to the participant (mean rule), participant accuracy (threshold 0) and AUC are computed on the scored folds; the reported value of a run is the best grid point on the scored folds (maximum accuracy and maximum AUC over the 216 points, chosen on the same folds that are scored, as in the published protocol). The vote-aggregation versions (`vote_acc`, `vote_auc`) are stored as a supplement. The scale/select step is cached per (fold, k); this gives numerically identical inputs to the SVC and is checked against the verbatim function on one pairing seed.
- Real-label reference: reproduction pairing seeds 1 and 2 (stored in `results/audit/followup_log.txt`: accuracy 0.7179 at both; AUC maximum 0.7211 and 0.6711). They are re-run with the same code to confirm the values; pairing seeds 3-10 are added as a sensitivity (real labels, 216 points).
- Null: N_B2 >= 200 shuffles (target 300 if timing allows; fixed in Amendment 1). Shuffle j: participant labels permuted between participants with `default_rng([20261202, j])`; class-paired folds rebuilt from the shuffled labels with pairing seed 5000 + j (same pairing function as the audit); full 216-point grid; record the maximum accuracy, maximum AUC, maximum vote accuracy, maximum vote AUC, and the median AUC over the grid.
- Statistics: null distribution (mean, SD, 2.5/50/97.5/99 percentiles, maximum) of best-of-grid accuracy and best-of-grid AUC. p_acc = (1 + #{null max-accuracy >= 0.7179}) / (1 + N_B2); p_auc_high = (1 + #{null max-AUC >= 0.7211}) / (1 + N_B2); p_auc_low = (1 + #{null max-AUC >= 0.6711}) / (1 + N_B2). All one-sided. Ties count as >= (conservative).
- Reading: if p is large, the real-label reproduction is not above what the search produces on pure noise.

## 4. Limits stated in advance
Permutation nulls test "no label-feature relation" and are not nulls of the exact Phase 4 bootstrap; the Delmas non-inferiority p is a shift approximation; Chen's within-participant permutation of trial types keeps the control-control structure random; the Mazza baseline uses 3 repeats against 5 for ours (as stored); machine load from other tracks running at the same time affects timing only, not results.
