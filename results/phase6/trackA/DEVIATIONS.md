# Deviations and clarifications, Phase 6 Track A

Nothing here changes a definition or decision rule in `PREREG.md`. Items 1 to 3 are where the closest valid version was done; the rest are clarifications of how an ambiguous line was read.

1. **Run order.** A3 was run before A2 and A7 (it only needed stored statistics). The order of the files in `card.md` is the plan's order. No result depends on the order.
2. **A1, cascade.** The cascade emits binary decisions, so it has one operating point, not a curve. It is compared with I2b's curve at the cascade's own realised FPR, re-evaluated inside every bootstrap resample (PREREG section 2 says "a single operating point").
3. **A4, "ours at 1000 Hz".** The Phase 4 unified pipeline exists only at 30 Hz. "Ours" at 1000 and 30 Hz is the Phase 2 raw-feature model ALL_z + LR (`ALLz_lr_1000` with 14 features incl. microsaccade rate, `ALLz_lr_30` with 13). The Phase 4 unified 30 Hz result is added as a third row (stored statistics, plus its detection and realised FPR at the stored 7% threshold). "Published model" = P4 + SVM (the published features rebuilt label-free); `book_svm` (the authors' own label-dependent table + SVM) is added as a fourth reference. The expected-innocent sensitivity (50 pseudo-probe draws) is a point estimate only, with no bootstrap CI.
4. **A4, G4 and G5 windows.** G4 and G5 exist only as 32-trial sets, so their windows are half as long as G1 to G3's (64 trials). This is a limitation of the data, not a choice; 32_g3 is shown as a labelled extra row.
5. **A1, choice of control direction.** PREREG fixed z_c1 as the primary null before any computation. The result is sensitive to this choice (pAUC difference I2b minus rate rule +0.35 with z_c1, +0.17 [-0.02, +0.34] with z_c2, +0.24 with the original double-counted pool). All three are reported in `results.json` and the card; none was dropped.
6. **A2, Chen and unequal repeat counts.** The Chen primary is a detection rate, which has no AUC definition, so the AUC rows are person AUC and trial AUC (labelled as such). For Colasanti the baseline files hold 3 repeats and the unified run 5; each arm uses its own repeats in V0, V1 and V2 (V0 reproduces the Phase 4 stored deltas to 1e-9). In V1 the rank transform is applied once to the full sample within each repeat, then resampled with the participants.
7. **A6, minimum detectable single AUC.** Computed with the Hanley-McNeil SE under the null (AUC 0.5) for the test and the SE at the alternative for the power term; it gives 0.72 (n = 39), 0.69 (n = 57), 0.66 (n = 78). The review quoted 0.75, 0.71, 0.68, apparently with a different convention. Delta MDEs use the bootstrap SE of the stored scores (as the review did) and reproduce its table to within 0.01.
8. **A8, per-fold metric.** Person-task folds contain 1 to 3 participants (Celniak, Preti) or 7 to 16 (Colasanti). Folds with one class give no AUC and are dropped: Celniak 3 of 60, Preti A and B 9 of 90 each. The Nadeau-Bengio correction was derived for accuracy-type metrics; with per-fold AUCs on 2-participant folds the fold-level variance is large, which widens the corrected CI. Colasanti uses the 3 repeats common to both arms. Delmas combines the per-set variances as independent (df = 14).
9. **Card wording.** The first version of the card paragraphs for A1, A2, A4 and A5 was rewritten after the results were seen, to add the sensitivity numbers (A1: control direction; A2: the Colasanti sentence; A4: published-table comparison; A5: interaction values). The numbers in `results.json` were not changed. A1 was also first run with a slow loop that was vectorised before its first completed run (same arithmetic).
