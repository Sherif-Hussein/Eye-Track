# PREREG: Phase 4 unified pipeline run

Written 2026-11-02, before any real-label outcome of this experiment was computed. Never edited after the real run starts; deviations go in `DEVIATIONS.md`. Code: `src/edd/unified.py`, `scripts/phase4_unified.py` (new files only). Real-label stages refuse to run until the coordinator creates `GO_AHEAD.txt` in this folder. Only label-shuffled smoke runs (scratch folder) were made.

## 0. What was known before this document (disclosure)
The Phase 2 and 3 tracks produced results on every one of these datasets, so the design below is informed by them, and the feature families in particular were not chosen blind. Where a choice below follows a Phase 2/3 finding, this is stated. The choices were fixed by the rule "everything the extractor provides for the sensor and task, in one fixed family per dataset", not by ranking scores, and no new feature or hyperparameter is introduced beyond what the tracks already computed. Selection of the final recipe is therefore not independent of the earlier results; the confirmatory value of the run lies in fixed folds, a fixed recipe, paired comparison with stored honest baselines, and full reporting.

## 1. The method (identical for every dataset)
1. Input: 30 Hz where raw samples exist (Delmas: anti-aliased polyphase decimation of the decoded 1000 Hz EyeLink samples, as in the tracks; Chen: the stored 100 Hz epochs decimated by 3/10, because the 1000 Hz stream is not stored beyond the 100 Hz epochs); native rate otherwise (Celniak 250 Hz Tobii, Preti fixation-level EyeLink, Mazza webcam aggregates).
2. Label-free features, vectorised extraction (`delmas_fast`, `celniak_fast`, `preti_fast`; Chen and Mazza vectorised by construction). Lists in section 2, fixed now.
3. Within-participant standardisation, label-free, each participant's own data only (section 2 gives the participant's own reference per dataset). Afterwards median imputation and column standardisation are fitted on training rows only (inside every fold), so that one C penalises all features equally.
4. L2 logistic regression, `class_weight="balanced"`, lbfgs. C from the single grid `logspace(-3, 1, 9)` = {0.001, 0.0032, 0.01, 0.032, 0.1, 0.32, 1, 3.2, 10}, chosen by the mean per-fold AUC over participant-grouped inner folds (`StratifiedGroupKFold`, k = min(5, n_train_participants // 3), shuffle, seed = 1000 x repeat + fold), ties to the smaller C, then refit on all outer-training rows. No ensembles, no feature selection, no other tuning.
5. Person-level decision at thresholds calibrated on training participants only. Training participants' statistics come from their inner out-of-fold scores at the chosen C. Two operating points, both stored: `tau_eer` (training FPR closest to training FNR; HTER, accuracy etc. reported at it) and `tau_fpr7` (the floor(0.07 m)-th largest training negative statistic, decide positive when `stat > tau`; detection and realised FPR reported). Person statistic: Celniak, Preti, Mazza = mean of the participant's row scores; Delmas = CIT z of known vs irrelevant images (negatives = simulated innocent, same person with as many random unknown faces as pseudo-probes, as in the track); Chen = one-sided-t z of familiar vs control trials (negatives = control-1-vs-2 z, both directions), per experiment, exactly as `chen_confirm`.
6. Metrics for every task: trial/row level and person level, via `edd.metrics` (accuracy, balanced accuracy, sensitivity, specificity, precision, F1, MCC, AUC, EER, HTER), mean and SD over repeats.

## 3. Comparators (stored out-of-fold scores on the same folds)
Delmas: P4 SVM at 1000 Hz (`phase2/delmas_raw/oof_scores.csv.gz`, tag `P4_svm_1000`). Chen: the paper's rate rule and the confirmed I2b (`phase3/chen_confirm/checkpoints`). Celniak: honest paper-feature SVM (`trials_baseline_svm_paper.csv`). Preti Level A: `B_ocular`; Level B: `B_fusion`. Mazza: published logistic regression on the 36 features (`base_pub36_lr_unreg`). The confirmed I2b result is reported separately and is not swapped in for the unified Chen model. Liar's Dice is excluded (awaiting the authors' permission).

## 4. Primary tests (one per dataset comparison; seven in the Holm family)
Paired participant-cluster bootstrap, 2000 resamples (participants drawn with replacement, same draws for both arms), `numpy.random.default_rng(20261103)`, percentile 95% CI, bootstrap one-sided p = (1 + #{delta in the null direction}) / 2001. Scores are averaged over repeats per decision unit.

| # | Test | Metric | Hypothesis |
|---|---|---|---|
| 1 | Delmas | image-level AUC pooled within each of the six group-sets, mean over sets, unified 30 Hz minus P4 SVM 1000 Hz | non-inferiority, H0: delta <= -0.02 (margin as agreed) |
| 2 | Chen | pooled person detection rate at the calibrated FPR <= 7% threshold (56 participants), unified minus rate rule | superiority, one-sided delta > 0 |
| 3 | Celniak | participant AUC, unified minus honest SVM | superiority |
| 4 | Preti Level A | participant AUC vs `B_ocular` | superiority |
| 5 | Preti Level B | participant AUC vs `B_fusion` | superiority |
| 6 | Mazza G2 vs G3 | participant AUC vs published LR | superiority |
| 7 | Mazza guilty vs innocent | participant AUC vs published LR | superiority |

Holm family: exactly these seven raw p-values (the Delmas p is the non-inferiority p), alpha = .05. Raw and Holm-adjusted p are both reported, with the CI. A pass for the Delmas test means non-inferiority; for the others, a Holm-adjusted p < .05 and a CI excluding 0. Everything else (per-dataset secondary metrics, per-set Delmas deltas, I2b comparisons, trial AUC, controls) is descriptive: point estimates and CIs, no decision.
- **Delmas sensitivity (stated in advance):** group 3 counted once, i.e. set `32_g3` dropped (same 15 people as `64_g3`); reported next to the primary with the same bootstrap.
- **Celniak control:** the 19 features + calibration error as covariate (log validation error), vs the honest baseline, vs the unified model, and the validation error alone as a reference. Reported whatever the outcome; interpretation guide: if the control is not different from the unified model, the unified signal adds nothing beyond calibration quality.
- **Preti sensitivity:** contrast-only versions (section 2). **Chen descriptive:** person AUC and trial AUC vs rate rule and vs I2b, realised held-out FPR of every arm (a realised FPR more than 3 points above the rate rule's is flagged as a caveat, not a change of the test).

## 5. Optional cascade on Chen (separate family: one test, alpha .05, outside the seven)
- Stage 1: the unified recipe on 10 features (pupil and dx at 500 ms resolution; 5 + 5), within-participant z, same C grid and folds.
- Deferral rule, fixed on training participants only (from the stage-1 inner out-of-fold statistics): decide "detected" when the stage-1 statistic exceeds tau_hi (at most 2% of the training null above it); decide "not detected" when it is at or below tau_lo (10th percentile of training familiar-statistics); defer everything in between to stage 2.
- Stage 2: the confirmed I2b model with its own calibrated FPR <= 7% decision (its stored statistics from the confirmatory run, same folds).
- Judged on: person detection at the realised cascade FPR (reported next to it) vs I2b: non-inferiority, margin -0.05 absolute detection, paired participant bootstrap, one-sided; and on mean cost per decision = stage-1 p50 latency + defer rate x I2b p50 latency (single thread, from the efficiency stage). The defer rate is reported overall and by case type.

## 6. Notes on the recipe stated in advance
- Within-participant standardisation applies where the participant's own rows contain the contrast (Delmas, Chen). For person-labelled data it is realised as the participant's own reference contrast (Celniak, Mazza, Preti contrast columns). Preti keeps raw levels in the primary arms because liar vs truth-teller is a between-person label (levels carry it; Phase 2 found control-normalising everything collapses the RT signal); the strict version is the pre-declared sensitivity above. Within-person standardisation may lower Chen against `I2b`; that is accepted.
- The reported thresholded numbers use `score > tau`; AUC and EER are threshold-free.
- Calibration plots use sigmoid(logit) of a balanced model, i.e. relative to a balanced prior.

## 7. Efficiency measurements (stage `efficiency`)
Same session, single thread (`threadpool_limits(1)`), baseline and unified timed in interleaved rounds (order alternated each round), 6 rounds; reported value = median over rounds of each round's p50 and p95. Per dataset: p50/p95 latency per decision unit, throughput (decisions/s), samples/s and real-time factor against the sensor rate where a raw signal is processed (Delmas, Celniak; Chen from the preprocessed 100 Hz epochs, raw EDF reading excluded), peak Python-tracked memory (`tracemalloc`; the Delmas fast path is reported at chunk 64 and chunk 8 because it trades memory for time), pickled model size and stored parameters (LR: coefficients + intercept + median/mean/scale per feature; SVM: support vectors x features + dual coefficients + intercept + 3 per feature). Baselines: Delmas P4 SVM 1000 Hz with the original code; Chen rate rule (plus I2b and the cascade stage 1 for the cascade cost); Celniak paper-feature SVM (C=1, gamma=0.1, fixed from the track's card) with the original extractor; Preti `B_fusion` with LR (C=1, fixed) and the original extractor; Mazza the 36-feature LR. Models are fitted on all data of the task for timing only. Machine load is not controlled, so absolute times are upper bounds; ratios are the claim.

## 8. Figure data (the charts are made by the senior analyst; this run writes data only)
`figdata/` (tidy CSVs, columns documented in `figdata/README.md`), all from out-of-fold scores: (1) `roc_det_curves.csv` and `roc_det_eer.csv` per dataset and model with participant-bootstrap bands, EER point and threshold; (2) `score_distributions.csv` (one row per decision unit with label, score, thresholds); (3) `learning_curve.csv` (AUC at 25/50/75/100% of training participants, mean and CI) and `validation_curve.csv` (log-loss and AUC against C, train vs held-out); (4) `feature_weights.csv` (standardised coefficients with CI across folds x repeats); (5) `calibration_bins.csv` (supplementary); plus `efficiency.csv`. No t-SNE, UMAP or other embeddings. Method text values (logistic loss equation, tuned C per dataset) come from `results.json` (`C_chosen_counts`).

## 9. Reporting rule
Everything is reported regardless of outcome, including negative, null or inconclusive results. One run of the full design; no change of features, grid, folds, tests or margins after the real run starts. Bugs found during the run are fixed in new code only, debugged on label-shuffled data, and logged in `DEVIATIONS.md`. n_jobs <= 4, no package changes, existing files and frozen folders are never modified. Checkpoints: one file per task x repeat in `checkpoints/`; `RESUME.md` is updated after every stage.

## 10. Known limits stated in advance
Same people as the tracks (new recipe, not new samples); Chen at 30 Hz is simulated from 100 Hz epochs, Delmas from 1000 Hz, neither adds webcam-level spatial noise (Phase 3 webcam test was negative); the Celniak groups differ in calibration error; Preti Level A fixation-derived measures are excluded but pupil and blink measures still depend on trial duration; the Delmas image-level metric is not the paper's label-dependent table; Chen's control-vs-control negatives are a surrogate for innocent people.

## 11. Analysis A: sampling-rate test on Chen (added 2026-11-02 before any real-label run; code `chen_rate` stage)
- **Reference rate.** The highest rate cached for both channels is 100 Hz: the stored epochs of pupil (blink-reconstructed at 1 kHz by the authors' pipeline, then 10x down), gaze x/y and missing fraction are 100 Hz; only a raw 1 kHz pupil trace (`pa_1k`) is also cached, with no gaze counterpart. Rebuilding a 1 kHz reference would need a new blink-reconstruction and a gaze re-extraction and is not done. So the tested rates are **100 Hz (reference), 60 Hz and 30 Hz**; the claim covers decimation from 100 Hz, not from 1000 Hz (the Delmas test covers 1000 Hz).
- **Decimation.** Same anti-aliased method as the Delmas track: gaps linearly interpolated, `scipy.signal.resample_poly` by 3/5 (60 Hz) and 3/10 (30 Hz) with `padtype="line"`, applied to each epoch channel before any feature step (60 Hz: 6 samples per 100-ms bin; 30 Hz: 3). The I2b rate channel is recomputed as diff of the decimated pupil smoothed with a Hanning window of the same 250 ms (15 and 8 samples); at 100 Hz the stored channel is used (identity of the 125 I2b features with the confirmatory matrix is checked: max abs diff recorded in `results_chen_rate.json`).
- **Models.** (i) The unified-recipe Chen model of section 2 (75 features: pupil, dx, dy bins, within-participant z, L2 LR, shared C grid) at 100, 60 and 30 Hz. (ii) The confirmed I2b pipeline (125 features: pupil, rate, dx, dy, missing fraction; SelectKBest, C in {0.003, 0.03, 0.3}) at 100 (the stored confirmatory scores), 60 and 30 Hz, run with `chen_confirm`'s own arm function on the same folds. Comparator: the paper's rate rule at 100 Hz (stored confirmatory scores). Folds: the frozen confirmatory `folds.json` (3 repeats x 10 folds, 56 participants).
- **Primary outcome: trial AUC** (familiar vs control trials, repeat-averaged out-of-fold scores pooled over the 56 participants). Paired participant-cluster bootstrap, 2000 resamples, one stream (seed 20261114), the same resampled participants for every model and rate in a resample.
- **Tests and Holm families (stated now).** A1 (non-inferiority, margin 0.02 AUC, H0: delta <= -0.02): the low-rate model minus the same model at 100 Hz, for {unified, I2b} x {60, 30 Hz}, four tests. A2 (superiority, one-sided): the low-rate model minus the rate rule at 100 Hz, same four models, four tests. Holm is applied within A1 and within A2 separately (they answer different questions: the efficiency claim and the accuracy claim). These two families are separate from the seven-test family of section 4 and from analysis B. Non-inferior = Holm-adjusted p < .05 (the one-sided lower bound then lies above -0.02).
- **Secondary (descriptive, CIs, no decisions):** person AUC and person detection at the calibrated FPR <= 7% (with realised FPR) for every model and rate; the detection difference to the rate rule with its bootstrap CI. Output also as `figdata/chen_rate_curve.csv`.
- **If a channel cannot be decimated meaningfully:** gaze exists only at 100 Hz, so nothing above 100 Hz is tested; all channels are decimated the same way. Pupil values at 60/30 Hz derive from a trace that was already smoothed and 10x down-sampled at 1 kHz by the authors' pipeline.

## 12. Analysis B: data-driven adaptive fixation threshold under simulated webcam noise (added 2026-11-02 before any real-label run; `webcam_adaptive` stage)
- **Setup (read from `results/phase3/webcam_noise/`, not modified):** the same 30 Hz decimated cache (`cache_30hz`), the same noise model (per-participant Rayleigh offset with mean L, jitter SD 0.5 + 0.25 L deg per axis, 10% dropout at L > 0; `edd.webcam_noise.apply_noise`), the same seeds (`[20261102, draw, participant]`) and draws (3 per non-zero level; draw 0 clean), the frozen Delmas folds, image-level AUC pooled within the six group-sets on repeat-averaged scores, mean over sets, mean over the 3 draws.
- **Model:** the unified-recipe Delmas model of section 2 (the same 13 features as `ALL_z`, within-participant z, L2 LR, the shared C grid). It is the track's ALL_z feature set with this study's grid and inner folds, so the clean-level figure is the unified Delmas number with the adaptive threshold, not a replay of the Phase 3 file. Features by `delmas_fast` (equivalent to the original code; verified in Phase 3) with the threshold replaced.
- **Threshold, estimated per participant from that participant's own (noisy) samples, without labels and without knowledge of the noise level.** Velocity = central difference over +-1 sample (66 ms at 30 Hz) of the participant's gaze, all trials pooled; NaN where a neighbour is missing.
  - **Primary rule `ek` (median-based, Engbert & Kliegl 2003 style):** per axis SD = sqrt(median(v^2) - median(v)^2), threshold = max(30 deg/s, 6 x sqrt((SDx^2 + SDy^2) / 2)). k = 6 is the default velocity threshold of the method as listed in the `saccadr` package documentation (alexander-pastukhov.r-universe.dev, "Implemented Methods"), which I read; the original paper was not read. The floor at 30 deg/s (the clean pipeline's I-VT value) was added after I saw label-free threshold distributions (the unfloored rule gives about 8 deg/s on clean 30 Hz data, below what is plausible for fixations); with the floor, clean data keeps 30 deg/s, so the clean level shows whether the rule changes anything where there is no noise, and noise can only raise the threshold. The combination of axes into one speed threshold is my adaptation (the original criterion is elliptic).
  - **Secondary rule `nh` (Nystrom & Holmqvist 2010, Behav Res Methods 42:188-204; as described in the same `saccadr` documentation, paper not read):** peak threshold PT starts at 100 deg/s, PT = mean + 6 SD of the velocities below PT, repeated until it changes by less than 1 deg/s; the fixation threshold is the onset threshold mean + 3 SD of the velocities below the converged PT (cap 1000 deg/s, no floor). Disclosed: label-free inspection showed this rule gives thresholds around 200 deg/s on 30 Hz data (the velocity distribution is far from Gaussian), so it is reported for transparency only and is expected to be poorly suited at this sample rate.
  - Both are fixed here; no k, floor or iteration parameter is changed after the run.
- **Levels:** L in {0, 1, 1.5, 2, 3, 4} deg (clean level included, draw 0 only). **Test:** non-inferiority of the adaptive-threshold model at each level against the clean P4 SVM at 1000 Hz (stored scores), margin 0.02 AUC, paired participant bootstrap within sets (2000 resamples, one stream, seed 20261126, the same resampled participants for the reference and every level), H0: delta <= -0.02, one-sided p = (1 + #{delta <= -0.02}) / 2001.
- **Holm family:** the six levels, separately for each rule (primary `ek`: six tests; secondary `nh`: six tests). Headline: the largest L such that all levels up to it are non-inferior (Holm p < .05), as in the Phase 3 pre-registration. The Phase 3 oracle-threshold results (fixed 30 deg/s and jitter-scaled threshold) are cited as stored context and are not recomputed.
- **Not modelled:** the same limits as Phase 3 (constant offset, no drift, no eccentricity dependence, research-grade tracker as the noise-free base).
