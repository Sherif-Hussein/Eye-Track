## 1. E2: conservative false-positive threshold
**Data.** Stored out-of-fold results only; no model is refitted. Held-out decisions: `results/phase4/unified/oof/*_persons.csv.gz` (columns repeat, fold, unit, kind, y, stat, tau_fpr7 ...). Training-negative statistics: the nominal `tau_fpr7` was derived in `edd.unified.persons_mean / persons_cit / persons_chen` from the *inner* out-of-fold scores (`inner_oof` in `results/phase4/unified/checkpoints/<task>__f100__r<repeat>.pkl`) of the outer-training participants. These stored scores are not in the oof person files, so the script re-applies exactly the same person-level statistic code to the stored inner scores (this uses the stored checkpoints, not a refit) and collects the training negative statistics per (repeat, fold). Check built in: the recomputed nominal threshold must equal the stored `tau_fpr7` (max abs diff <= 1e-9 for every fold); a task failing the check is reported as such and not used. The Delmas `persons_cit` simulated innocents use the same seeded random generator as in Phase 4.

**Nominal rule (stored).** tau_nom = the floor(0.07 m)-th largest training negative (0-indexed in descending order); decide positive when stat > tau.

**Conservative rule (new).** For a fold with m training negatives, let U(k, m) be the one-sided 95% Clopper-Pearson upper bound for k exceedances: Beta(0.95; k + 1, m - k) quantile (1 if k = m). Let k* be the largest k with U(k, m) <= 0.07. The conservative threshold is the smallest tau with #{training negatives > tau} <= k*, i.e. tau_cons = the k*-th largest training negative (0-indexed, descending; same convention as the nominal rule). If no k >= 0 satisfies the bound (U(0, m) > 0.07, i.e. m < 42) the rule is infeasible: tau_cons = +infinity (the rule flags nobody), and this is reported as "infeasible", not hidden. Detection is then 0 by construction and the table says so.

**Chen.** Following `persons_chen` exactly, the Chen null pools both control directions (z_c1 and z_c2) of every training participant (m = 2 x participants of that experiment), and the threshold is computed per experiment. Because z_c2 = -z_c1 exactly, the pooled null counts each participant twice and the binomial bound is optimistic; so the primary Chen row is the pooled-null rule (identical to the stored nominal rule), and a sensitivity row uses z_c1 only (m = participants, independent). Both are reported.

**Held-out outcome.** For each task and threshold: detection = mean over positive units of (fraction of repeats in which stat > tau), realised FPR = the same over negative units (Delmas: the simulated innocents; Chen: both control rows). Unit = participant (Delmas and Chen: a participant carries both classes). Primary 95% interval: Clopper-Pearson on (round(rate x n_units), n_units) with n_units = distinct participants of that class (this treats the repeat-averaged decision as a binomial count, an approximation stated in the table); secondary: participant-cluster bootstrap, B = 2000, seed 20261301, percentile. Rows report: number of folds with a feasible conservative threshold out of all folds, mean m, mean k*, mean nominal and conservative thresholds, and the smallest m for which the rule is feasible at k* = 0 (m = 42).

**Tasks.** Every task with a person file and a calibrated threshold: Delmas `64_g1 64_g2 64_g3 32_g3 32_g4 32_g5`, Chen (all, exp 1, exp 2), Celniak `unified` (primary) with `ctrl_valcov` and `ref_valonly` (controls, labelled), Preti `A_ocular`, `B_ocular_rt` (primary) with the two contrast-only arms (secondary), Mazza `g2_vs_g3`, `guilty_vs_innocent`. The cascade/stage-1 files are not used.

**Reading rule (fixed now).** "Conservative" is judged by the realised held-out FPR with its interval against 7% (point estimate <= 7% and CP upper <= the nominal's), and its price by the detection. Nothing is a hypothesis test. If the rule is infeasible in most folds of a task, the paper statement is "a finite-sample guarantee cannot be given at this training size", not a number.

## 2. E3: Chen corrected repeated-CV intervals
**Data.** Phase 3 confirmatory checkpoints `results/phase3/chen_confirm/checkpoints/repeat{0,1,2}.pkl` (arms `rate_rule`, `I2b` = pupil bins + gaze, columns z_fam, z_c1, z_c2, detect_cal) and `chen_unified_persons.csv.gz` (unified pipeline). Folds are the frozen outer folds (3 repeats x 10 folds, J = 30).

**Intervals.** Same method as Track A8 (`scripts/phase6_a8_corrected_cv.py`): per-fold difference d_rf (arm minus rate rule), Nadeau-Bengio corrected variance (1/J + n_test/n_train) s^2 with n_test/n_train the mean over folds of test/(N - test) participants, t with J - 1 df, naive 1/J variance shown beside it, across-repeat t (R - 1 df) as the conservative check. Two metrics, for unified minus rate rule and for I2b (pupil bins + gaze) minus rate rule (and, descriptive, unified minus I2b):
- (a) detection: per-fold detection rate among the fold's familiar participants at the calibrated FPR <= 7% threshold. Taken from `results/phase6/trackA/results.json` (A8) and re-derived from the checkpoints as a check (must agree to 1e-9; the re-derived value is reported if not).
- (b) person AUC (new here): per fold, AUC of the person z statistic, the fold's familiar z_fam as positives against the fold's control z_c1 and z_c2 as negatives (the pre-registered pooling of A2), each repeat's own scores (no repeat averaging inside a fold). Sensitivity: z_c1 only. Folds with one class would be dropped (none expected).

**Bootstrap companion.** The participant-cluster bootstrap interval (B = 2000, seed 20261302, 56 participants resampled jointly across arms) of the pooled person-AUC difference (repeat-averaged statistics, A2 definition) for the same two comparisons, so that the corrected and the bootstrap intervals can be quoted side by side. The detection bootstrap intervals are quoted from the Phase 3 `results.json` (I2b) and Phase 4 `results.json` (unified).

**Reading rule.** An interval that contains 0 is reported as "does not exclude 0"; no claim is made from the point estimate alone.

## 3. E1: like-for-like timing
**Design.** 2 x 2 x 2 factorial on one participant (Sj_04, the participant of the Phase 4 timing; 64 trials x 5.5 s at 1000 Hz; `results/phase3/fast_extraction/cache/delmas_decoded/p04.npz`): sampling rate {1000 Hz, 30 Hz} x code {original (`phase2_delmas_raw.raw_to_scores`: per-trial `delmas_raw.trial_features`, Python loops and per-image aggregation as in the track) vs vectorised (`edd.delmas_fast.raw_to_scores_fast`, chunk = 64)} x model {published = P4 features (dwell_1, dwell_2, n_fix, n_visit), RBF SVM (the Phase 4 baseline model); ours = the unified recipe: z-scored features within participant, deployed LR (`edd.unified.DeployLR`) fitted on the Delmas 64-trial groups}. Our feature set is the Phase 4 one at 30 Hz (13 features, no microsaccade rate); at 1000 Hz it is the same 13 plus the microsaccade rate (14 features, as ALL_z in the track; the detector is part of the timed path). Sensitivity cells at 1000 Hz with the 13 features (both codes) isolate the microsaccade cost. Timed region (identical to Phase 4): sensor-rate samples of the whole session -> I-VT -> features -> per-image aggregation -> (z-scoring) -> model scores for the 64 images; decimation to 30 Hz is done once outside the timer (simulated sensor output), model fitting outside the timer.

**Procedure.** One Python process, single thread (OMP/OPENBLAS/MKL threads = 1 and `threadpool_limits(1)`), 3 warm-up calls per cell, then R = 8 rounds; in each round every cell is run in a block of n_run calls (original 1000 Hz cells: 4, original 30 Hz: 8, vectorised: 30), the cell order is reversed on alternate rounds. Reported per cell: p50 = median over rounds of the per-round median; p95 = 95th percentile of all timed calls pooled over rounds (the per-round p95 of 4 calls is not informative; the median of per-round p95 is also stored); range of per-round p50. Scores of original and vectorised code for the same (rate, model) are checked equal (max abs diff reported).

**Quiet-machine rule.** The timing run starts only when no process command line contains `phase6_trackB` (PowerShell `Get-CimInstance Win32_Process`), checked by the script itself before and after the run, with the whole timing flagged invalid if one appears during it. Processes containing `phase7_trackD` are recorded; if running, timing proceeds and the load is written to `DEVIATIONS.md` (with the system CPU percent sampled before, between rounds and after). The script also stores the listing of all python command lines at start and end.

**Decomposition.** Let T(rate, code, model) be the p50. Baseline B = T(1000, original, published) (Phase 4's 183 ms cell) and final F = T(30, vectorised, ours) (Phase 4's 3.15 ms cell). Total = B / F. Factors on the log scale: rate = log T(1000, c, m) - log T(30, c, m), code = log T(r, original, m) - log T(r, vectorised, m), model = log T(r, c, published) - log T(r, c, ours). Reported (i) as the sequential path rate -> code -> model starting from B, and (ii) as the Shapley average over the six orders of the three factors (these sum exactly to the log of the total); (iii) the parts attributable to the method for the abstract = the rate factor and the model factor with the code held at vectorised for both models, the code factor being available to the published model too. A bootstrap over rounds (resampling the per-round p50s, 2000 draws, seed 20261303) gives intervals of each ratio. Timing covers one participant on one laptop (i7-8550U); this is stated.

**Reading rule.** A factor below 1 (e.g. our pipeline slower than the 4-feature SVM) is reported as such.
