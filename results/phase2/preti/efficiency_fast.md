## Notes

- **Load.** During the whole session the CPU was at 100% load: phase1_celniak.py (joblib workers) and phase2_chen.py (joblib workers) were running, so every timing is an upper bound and p95 values are inflated by contention. Original and fast were measured back to back in the same session under that load, so the ratios are indicative, not exact.
- **Saga.** I7_lr_en_I1_fusion uses the stochastic saga solver with a loose tolerance; ~1e-13 feature differences move its out-of-fold scores by up to 1.9e-3 (probabilities 4.7e-4), but the chosen hyper-parameters and the per-repeat AUCs are identical.
- **What changed.** Only feature extraction (pandas groupby over the fixation table, one Python call per trial) was replaced by NumPy `reduceat`/one-hot matrix products on pre-sorted arrays; the RT-only path reads one RT per trial and never touches pupil or blink columns. The model and sklearn inference are unchanged (inference-only differences are noise). When the input still has to be converted from the pandas DataFrame, ingestion costs about 3.4-4.2 ms per participant, which then dominates the fast pipeline (see the 'incl. DataFrame ingestion' rows).
- **Protocol.** Original: 100 runs for extraction and end to end (as `phase2_preti_efficiency.py`); fast: 2000 runs because the calls are about 100 times shorter; both 500 inference runs and 2 s throughput. Timings differ from the earlier `efficiency.json` (e.g. 105 vs 117 ms for `B_fusion`) because they were retaken now under different load.
